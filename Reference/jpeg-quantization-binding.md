# JPEG quantization table binding

The reader follows JPEG table meaning at each scan. T.81 B.2.2 assigns a quantization-table destination to each frame component; B.2.4 and B.2.4.1 define DQT destinations and replacement when a destination is redefined ([ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf), printed pages 36 and 39–40). The pinned libjxl source (`a7a9c787341cf703dede03c2009fa460cae5e5df`) appends definitions and caps the list at `kMaxQuantTables=4` (`lib/jxl/jpeg/enc_jpeg_data_reader.cc:302-331`), binds the first matching destination (`:884-902`), then finalizes after EOI (`:1041`).

This implementation replaces the active destination on each DQT. At SOS it binds the selected components to immutable table snapshots, preserving sparse destination indices and appending a new snapshot when a redefinition conflicts with an earlier component's binding. A component never selected by any SOS is bound to the final active table at EOI. That last behavior is a permissive incomplete-input policy, not a claim that such an input is valid under T.81.

The redefined and canonical fixture pair decodes to identical pixels with libjpeg. The canonical fixture supplies stable per-component quantizers and coefficient dumps for the parser and native serialization witness. The original redefined fixture is read by the pinned source, but its coefficient-dump utility reports global tables and is not an oracle for scan-latched bindings. These comparisons establish decoded equivalence and the intended table meaning; they do not claim a JPEG XL specification conflict or a porting defect.
