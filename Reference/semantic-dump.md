# Semantic dump (I-3)

A semantic dump lists the encoder decisions a JPEG XL codestream carries, as
named integer and float fields. Two sides write one:

- **Reference:** `jxl-harness dump <file.jxl>` decodes any bare codestream with
  the pinned libjxl (`Reference/libjxl.pin`) and records what the decoder state
  holds. It is used on the pinned libjxl's own `-e 4` output to make the
  committed fixtures (`Tests/JXLEncoderTests/Fixtures/semantic/*.sem`), and on
  this package's output for the local cross-check.
- **Swift:** `SemanticDump(swiftDecisions:)` in the tests builds the same fields
  from the Swift encoder's own decisions, so CI (which has no libjxl) compares
  Swift against the fixtures.

Comparison catches a changed decision even when the file still decodes and
its size is unchanged. Whole-file byte equality is never required: upstream
SIMD and float differences make it the wrong test.

## Text format

UTF-8 with LF line endings. The first line is exactly `jxl-semantic-dump 1`.
Every other line is one field:

```
<name> <kind> <count> <value>…
```

- `name`: `<category>.<field>[.<qualifier>…]`, made of `[a-z0-9_.]`. The
  category is the harness dumper that owns the field (one source file,
  `Reference/harness/src/dump_<category>.cc`).
- `kind`: `i` (64-bit signed integers, decimal) or `f` (float32: any decimal
  that parses back to the same float32; the harness writes `%.9g` in the C
  locale, Swift its shortest round-tripping form). Equal dumps may differ in
  text, so dumps are compared parsed, never as text.
- `count`: number of values that follow; 0 is allowed.
- Name components are nonempty. Float values must be finite. A final LF is
  optional when parsing; writers always include it. Parsers accept fields in
  any order and reject duplicate names.
- Fields are sorted by name and appear once each. Separators are single spaces.

## Comparison rules

`SemanticDump.differences(from:)` implements these; an empty result means the
dumps agree.

1. Integer fields compare exactly, element by element.
2. Float fields compare within the tolerance this document lists for that
   field. A float field with no listed tolerance is a difference
   (`noTolerance`), never silently compared.
3. A field present in only one dump, a kind mismatch or a count mismatch is a
   difference.
4. Only the first differing element of a field is reported. Differences are
   sorted by field name. Structure is checked before float tolerances.
5. ULP distance uses monotonic float32 bit ordering, with signed zeros
   distinct and adjacent (0 ULP means bit-identical). Absolute tolerance is
   inclusive. Nonfinite values never compare equal.

A test that compares only some categories restricts both dumps first
(`restricted(to:)`).

## Standalone entropy primitive fixtures

`Tests/JXLEncoderTests/Fixtures/entropy/*.input.sem` and `*.expected.sem` are
deterministic primitive probes generated by `Reference/make_entropy_fixtures.sh`
against the pinned full libjxl harness. Histogram inputs record counts,
`log_alpha_size`, and ANS strategy. An empty count vector and a nonempty
all-zero vector both represent an empty symbol stream: the pinned encoder emits
its three-bit empty-histogram marker, with no normalized symbols or alias
entries. Histogram outputs record normalized frequencies, serialized method
and shift, table frequencies, reverse map, bit count, and bytes.

Cluster inputs record mode, limit, histogram lengths, and flattened counts.
Outputs record the cluster map and histograms plus input and output token totals
to assert count conservation independently of the clustering result. The Swift
tests compare all fields normally except the exact named fields listed as
GER-3386 differences for individual fixtures; a changed difference set or any
other field still fails.

## Expected divergence

A fixture for a decision Swift hasn't translated yet still runs. Expected
divergence is recorded per corpus entry **and category**
(`SemanticCorpusEntry.knownIssues`, category → set of issues): each (entry,
category) pair is its own test case, and only a listed pair runs under
`withKnownIssue("GER-338x …")`, naming every issue that must land before it
matches. Other categories of the same entry are compared normally. A known
issue covers every field of its category for that entry, so it also hides any
other difference within that category. When one field diverges and the rest
should stay compared, the category owner splits the category or narrows the
field set covered by the known issue. A listed pair turns red the moment Swift
starts matching, which is the cue to remove it. Stage fixtures (`*.dump`) follow
the same rule per fixture (`StageFixtureKnownIssues`).

A fixture compared under a known issue verifies nothing: an inventory
`fixture` reference (`<path>#<category>` for a `.sem`) to it is a violation.
Never weaken a tolerance or drop a field to make a fixture pass.

## Adding a category (lanes B, C and D)

1. Add `Reference/harness/src/dump_<category>.cc`, which registers itself with
   `RegisterDumpCategory`; no shared source changes.
2. List its fields and any float tolerances below.
3. Add the Swift emitter for the same fields in
   `SemanticDump(swiftDecisions:)` and the category to
   `SemanticDump.swiftEmittedCategories`.
4. Regenerate the semantic fixtures (`Reference/make_semantic_fixtures.sh`) and
   their provenance rows.

A translation lane that changes `Encoder.encodeFrame`'s composition also
updates the test-side recomposition (`SwiftSemanticEncoding`) in the same
change: `recompositionMatchesEncoder` pins the two byte-identical and fails
until they agree.

## Categories

### `ac_entropy`

These fields describe the actual AC code tables selected for the frame. Tables
remain in transmitted order. `ac_entropy.kind` is 0 for prefix and 1 for ANS;
`ac_entropy.table_count` counts clustered code tables, while
`context_map.num_histograms` continues to count pre-clustered histogram sets.
Every table contributes one `(split_exponent, msb_in_token, lsb_in_token)`
triple to `ac_entropy.uint_config`. `ac_entropy.lz77_enabled` is zero for the
supported encoder path.

For ANS, `ac_entropy.ans.alphabet_lengths` gives the trimmed symbol count per
table and `ac_entropy.ans.frequencies` concatenates those normalized frequency
vectors. Only trailing zero frequencies are removed; internal zeros remain.
The flattened vectors have total frequency 4096 per table. The separate
`ac_entropy_alphabet.ans_log_alpha_size` category contains one value for ANS
and an empty array for prefix codes.

For prefix codes, `ac_entropy.prefix.alphabet_lengths` gives each effective
symbol count, `ac_entropy.prefix.depths` concatenates the trimmed depth vectors,
and `ac_entropy.prefix.singleton_symbols` contains the singleton symbol or -1
for a nonsingleton table. Singleton tables have zero decoder depths through
their singleton symbol, including the all-zero encoder representation, which
serializes as singleton symbol 0. Only trailing unused symbols are removed.

The actual encoder stores a one-bit placeholder for a prefix singleton; the
decoder consumes zero bits. The semantic dump records the decoder form. AC
LZ77 is unsupported and a reference frame with it enabled is rejected.

All fields below are `i` (signed decimal integers); no float tolerance is
needed for these categories. The supported first frame is single-pass VarDCT,
with DCT8 only and no preview, as produced by the corpus's e4 pixel path.
Other frame configurations are rejected rather than partially dumped.

| category | field suffix | layout |
|---|---|---|
| `frame` | `size` | width, height in pixels |
| `frame` | `encoding` | scalar; 0 = VarDCT |
| `frame` | `groups`, `dc_groups`, `passes` | one scalar each |
| `frame` | `xyb` | scalar boolean, XYB color transform |
| `frame` | `qm_scales` | X scale, B scale |
| `frame` | `loop_filter.gab`, `loop_filter.epf_iters` | boolean and iteration count, one scalar each |
| `coeff_order` | `nondefault_orders` | scalar derived bitmask: bucket bit is set iff any channel's decoded permutation differs from its natural order; only bit 0 (DCT8) can be set here |
| `coeff_order` | `dct8.c0`, `dct8.c1`, `dct8.c2` | 64 decoded coefficient indices per channel, in scan order |
| `block_context` | `dc_thresholds.c0`, `dc_thresholds.c1`, `dc_thresholds.c2` | ordered DC thresholds per channel, possibly empty |
| `block_context` | `qf_thresholds` | ordered quant-field thresholds, possibly empty |
| `block_context` | `ctx_map` | decoder's complete block-context map; channel order Y, X, B, then order bucket, quant-field bucket and DC bucket |
| `block_context` | `num_ctxs` | scalar count of block contexts |
| `context_map` | `num_histograms` | scalar count of pre-clustered histogram sets |
| `context_map` | `ac` | first pass's AC map, trimmed to `num_histograms * NumACContexts()`; no decoder padding |
| `quant_field` | `raw` | integer raw quantizer per block, whole-frame block raster order |
| `quant_field` | `global_scale`, `quant_dc` | one scalar each, exact integer `QuantizerParams` values |

`coeff_order.nondefault_orders` describes the decoded permutation, not the
signaling syntax. At the pinned e4 configuration upstream clears the signaled
bit for natural orders (`lib/jxl/enc_coeff_order.cc:231-233`), so its derived
and signaled masks agree. The Swift emitter compares the orders themselves
with `CoeffOrder.natural`; a separate Swift invariant test pins `isCustom`
exactly to the existence of a nonnatural order.

## What the decoder does not retain

Without a libjxl patch, these are not recoverable from the decoder
state after a decode. A category that needs one re-parses the section with
libjxl's public decoder primitives, or the lane records it as out of reach:

- the signaled coefficient-order mask (only its canonical form, derived from
  the decoded permutations, is dumped; at the pinned e4 config upstream never
  signals an explicit natural order, `enc_coeff_order.cc:231-233`);
- the ANS histogram precision (shift) choice: only the normalized counts survive,
  in the alias tables;
- quantized AC coefficients in a single-pass decode;
- quantized DC integers, and the modular DC tree, its histograms and context
  map (private to `ModularFrameDecoder`).
